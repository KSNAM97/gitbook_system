# Shell Script - exit 상태와 test 명령

> **Tag:** #Linux #ShellScript #Bash #ExitCode #종료코드 #Test #조건판단
> **핵심 요약:** 리눅스의 모든 명령은 종료 시 **종료코드(exit status)** 를 남기며, `$?` 변수에 자동 저장된다. `0`은 성공, `1~255`는 실패를 의미한다. `test` 명령(`[ ]`)은 파일·문자열·정수의 상태를 검사해 그 결과를 **종료 코드로 반환**하는 조건 판단의 기본 단위로, 조건문·반복문 전체의 토대가 된다.

---

## 1. 개요 (Overview)

`$?` 는 **바로 직전에 실행된 명령의 종료 코드**를 저장하는 특수 변수이며, 다음 명령을 실행하는 순간 그 명령 기준으로 즉시 덮어써진다. 따라서 확인하려는 명령 바로 다음 줄에서 `echo $?` 를 실행해야 하며, `echo $?` 자체도 하나의 명령이므로 그 값을 두 번 연속 확인하면 두 번째는 `echo` 자신의 종료 코드(보통 0)를 보게 되는 점에 유의해야 한다.

종료 코드는 `0`이 성공, `1~255`가 실패를 의미하며 숫자별로 대표적인 의미가 정해져 있다.

| 종료 코드 | 의미 |
|---|---|
| 0 | 성공 (Success) |
| 1 | 일반적인 에러 (모호한 오류) |
| 2 | Syntax error (사용법/옵션/문법 오류) |
| 126 | 명령을 실행할 수 없음 (Permission 문제 등) |
| 127 | 명령(파일)이 존재하지 않음 (command not found) |
| 128 + N | 신호(Signal)에 의해 종료됨 |

`Ctrl+C` 는 SIGINT(신호 2)이므로 종료 코드는 `128+2=130`이 되고, `kill -9 PID` 는 SIGKILL(신호 9)이므로 `128+9=137`이 된다. 자동화 스크립트에서 exit 코드가 중요한 이유는, 이전 명령의 성공/실패 판단이 곧 에러 처리·조건문·자동화 분기 로직의 전제가 되기 때문이다.

`[ 조건 ]` 은 `test 조건` 과 완전히 동일한 의미이며 표현만 다르다. `test`(`[ ]`)는 조건이 참이면 종료 코드 `0`, 거짓이면 `1`을 반환할 뿐 결과를 화면에 직접 출력하지 않으므로 항상 `$?`, `&&`, `||`, `if` 문 등과 함께 사용한다. `[ 조건 ]` 형태에서 대괄호 양쪽에는 반드시 공백이 있어야 하며, `[ $x -gt $y ]` 는 정상이지만 `[$x -gt $y]` 는 오류다. `test $x -gt $y` 와 `[ $x -gt $y ]` 는 동일하게 동작한다.

Bash 변수는 기본적으로 문자열이므로, 숫자로서 "크기"를 비교할 때와 문자열로서 "일치 여부"를 비교할 때 서로 다른 전용 연산자를 사용해야 의미가 명확해진다.

**숫자 비교**

| 연산자 | 의미 |
|---|---|
| `-eq` | 같음 |
| `-ne` | 다름 |
| `-gt` | 큼 |
| `-lt` | 작음 |
| `-ge` | 크거나 같음 |
| `-le` | 작거나 같음 |

**문자열 비교**

| 연산자 | 의미 |
|---|---|
| `=` | 같음 |
| `!=` | 다름 |
| `-z` | 빈 문자열인가 |
| `-n` | 비어 있지 않은가 |

문자열 비교는 반드시 큰따옴표로 감싸야 공백·빈 값 관련 오류를 피할 수 있다(`[ "$x" = "$y" ]`).

파일 테스트 옵션은 파일/디렉터리의 **존재 여부, 종류, 권한, 속성**을 자동화 스크립트에서 사전 검증할 때 사용한다. 예를 들어 백업 스크립트가 대상 파일이 존재하는지, 디렉터리인지, 읽기 가능한지를 실행 전에 확인해 사고를 예방한다.

| 분류 | 옵션 | 의미 |
|---|---|---|
| 존재 여부 | `-e` | 파일 또는 디렉터리가 존재 |
| 종류 확인 | `-f` | 일반 파일 |
| | `-d` | 디렉터리 |
| | `-L` | 심볼릭 링크 |
| | `-b` | 블록 디바이스 |
| | `-c` | 문자 디바이스 |
| 권한 | `-r` | 읽기 가능 |
| | `-w` | 쓰기 가능 |
| | `-x` | 실행 가능 |
| 속성 | `-s` | 파일 크기가 0보다 큼 |
| | `-nt` | x가 y보다 최신 파일 |
| | `-ot` | x가 y보다 오래된 파일 |
| | `-ef` | inode가 같음(하드링크 관계) |

마지막으로 `test` 의 논리 연산과 Bash 논리식은 차이가 있다. `-a`(AND), `-o`(OR)는 `test` 명령 자체의 구식 논리 연산자로 대괄호 **하나** 안에서 여러 조건을 결합한다. 반면 `[ 조건1 ] && [ 조건2 ]`, `[ 조건1 ] || [ 조건2 ]` 는 대괄호를 **각각 독립적으로 분리**하여 쉘 수준에서 연결하는 방식으로, 최근 스크립트에서는 후자가 더 명확하고 권장된다.

## 2. 표준 설정 템플릿 (Configuration)

> **적용 환경:** Bash 기반 Linux 셸 환경 (RHEL 계열 기본 `/bin/bash`).

### Step 1. 종료 코드 확인 기본 패턴

```bash
<명령어>
echo $?           # 직전 명령의 종료 코드 확인 (0=성공, 1~255=실패)
```

### Step 2. test / [ ] 기본 문법

```bash
test <조건식>
[ <조건식> ]        # [ 와 조건식, 조건식과 ] 사이 공백 필수
```

### Step 3. 숫자 비교 템플릿

```bash
[ $x -eq $y ]     # x == y
[ $x -ne $y ]     # x != y
[ $x -gt $y ]     # x > y
[ $x -lt $y ]     # x < y
[ $x -ge $y ]     # x >= y
[ $x -le $y ]     # x <= y
```

### Step 4. 문자열 비교 템플릿

```bash
[ "$x" = "$y" ]    # 문자열 같음
[ "$x" != "$y" ]   # 문자열 다름
[ -z "$x" ]        # 빈 문자열
[ -n "$x" ]        # 비어 있지 않음
```

### Step 5. 파일 테스트 템플릿

```bash
[ -e "$path" ]              # 존재 여부
[ -f "$path" ]              # 일반 파일
[ -d "$path" ]              # 디렉터리
[ -r "$path" ]              # 읽기 가능
[ -w "$path" ]              # 쓰기 가능
[ -x "$path" ]              # 실행 가능
[ -s "$path" ]              # 크기 > 0
[ "$file1" -nt "$file2" ]   # file1이 더 최신
```

### Step 6. 논리 연산 조합 템플릿

```bash
# 구식 test 논리 연산자 (하나의 대괄호 안)
test 조건1 -a 조건2
test 조건1 -o 조건2

# Bash 표준 논리식 (권장)
[ 조건1 ] && [ 조건2 ]     # 둘 다 참일 때 참
[ 조건1 ] || [ 조건2 ]     # 하나만 참이어도 참
```

## 3. 검증 및 트러블슈팅 (Verification & Troubleshooting)

### 3-1. 필수 검증 명령어

```bash
echo $?                    # 직전 명령 종료 코드
[ -e <path> ]; echo $?      # 파일 존재 여부를 종료 코드로 확인
type test                   # test가 내장 명령임을 확인
```

### 3-2. 트러블슈팅 시나리오

#### 시나리오 1. `[$x -gt $y]` 실행 시 문법 오류

- **증상:** `bash: [$x: 명령을 찾을 수 없습니다` 류의 오류.
- **원인:** 대괄호와 조건식 사이에 공백이 없음.
- **해결:**
  ```bash
  [ $x -gt $y ]     # 대괄호 양쪽에 반드시 공백
  ```

#### 시나리오 2. 존재하지 않는 명령을 실행했는데 원인 파악이 안 됨

- **원인 진단:** `echo $?` 값으로 원인 범주를 좁힌다.
  - `127` → 명령을 찾을 수 없음(오타, PATH 문제).
  - `126` → 권한 문제(실행 파일에 `x` 권한 없음).
  - `130` → 사용자가 `Ctrl+C` 로 중단.
- **해결:** 각 코드에 맞는 조치(오타 수정, `chmod +x`, 재실행 등) 수행.

#### 시나리오 3. 문자열 비교인데 숫자 비교 연산자를 사용해 예상과 다른 결과가 나옴

- **증상:** `[ "$name" -eq "root" ]` 처럼 문자열에 `-eq` 사용 시 오류 또는 의도치 않은 결과.
- **원인:** `-eq` 등은 숫자 전용 연산자.
- **해결:**
  ```bash
  [ "$name" = "root" ]     # 문자열 비교는 = 사용
  ```

#### 시나리오 4. 변수 값이 비어 있을 때 조건문에서 예상치 못한 오류 발생

- **증상:** `[ $x = $y ]` 에서 `$x` 가 빈 값이면 `[ = $y ]` 형태로 깨져 문법 오류 발생.
- **원인:** 변수를 따옴표 없이 참조하여 빈 값일 경우 토큰 자체가 사라짐.
- **해결:** 항상 큰따옴표로 감싸서 참조한다.
  ```bash
  [ "$x" = "$y" ]
  ```

#### 시나리오 5. `test` 결과를 화면에서 직접 확인하려 했으나 아무것도 출력되지 않음

- **원인:** `test`(`[ ]`)는 참/거짓을 종료 코드로만 반환하고 화면에 출력하지 않는 설계.
- **해결:** 결과를 보려면 `$?`, `&&`/`||`, 또는 `if` 문과 함께 사용.
  ```bash
  [ -f /etc/passwd ] && echo "파일입니다" || echo "파일이 아닙니다"
  ```

---

>  **핵심 요약**
> - `$?` 는 **직전 명령**의 종료 코드만 저장하며, 다음 명령 실행 즉시 덮어써짐
> - 종료 코드 : 0=성공, 1~255=실패, 127=명령없음, 126=권한문제, 128+N=신호종료
> - `test` = `[ ]`, 대괄호 양쪽 공백 필수, 결과는 화면 출력이 아닌 **종료 코드**로 반환
> - 숫자 비교(`-eq`,`-gt`...)와 문자열 비교(`=`,`-z`,`-n`)를 혼동하지 말 것
