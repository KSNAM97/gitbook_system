# Shell Script - 트러블슈팅 치트시트

쉘 스크립트 오류의 대부분은 ① 문자열 vs 숫자 혼동(계산은 `$(( ))` 필요), ② 따옴표 누락(공백·빈 값 처리 실패), ③ 대괄호/중괄호 문법 오류, ④ 카운터·break 누락으로 인한 무한 루프, ⑤ 배열·인자 전개 방식 혼동(`[@]` vs `[*]`) 다섯 가지에서 발생한다. **증상 → 원인 → 조치** 순으로 즉시 대응할 수 있게 정리한 문서다.

## 개요 (Overview)

쉘 스크립트 오류를 진단할 때 가장 먼저 확인해야 할 것은 ① `bash -n` 문법 사전 검사, ② `echo $?` 직전 종료 코드, ③ 변수 값이 실제로 무엇인지(`echo "$변수"`), ④ `bash -x` 로 전개 과정 추적, 이 4가지다. 특히 배열·위치 매개변수 관련 문제는 `bash -x` 와 `declare -p` 로 실제 전개 결과를 보는 것이 가장 빠르다.

"분명히 맞게 짰는데 안 된다"는 문제의 90%는 대괄호 공백 누락(`[$x]`), 변수·인자 따옴표 누락(`$1` → `"$1"`), 문자열 값에 숫자 비교 연산자 사용, 중괄호 확장에 변수 사용 시도, `[@]` 대신 `[*]` 사용, 이 다섯 가지 패턴에서 발생한다.

## 증상별 즉시 대응표 (Configuration)

### 2-1. 변수 · 산술 연산

| 증상 | 원인 | 조치 |
| --- | --- | --- |
| `echo $a+$b` 가 `10+20` 처럼 문자열로 출력됨 | Bash 변수는 기본 문자열 | `echo $(( a + b ))` 사용 |
| `arr=A B C D` 실행 시 `B: 명령을 찾을 수 없습니다` | 공백 있는 값을 따옴표 없이 대입 | `arr="A B C D"` |
| `let x = 5 + 3` 오류 | 공백 있는 식을 따옴표 없이 실행 | `let "x = 5 + 3"` |
| `expr 10 * 2` 오류/파일목록 출력 | `*` 가 글롭으로 먼저 해석됨 | `expr 10 \* 2` |
| `expr` 결과가 변수에 안 들어감 | `expr` 는 화면 출력만, 자동 저장 안 함 | `sum=$(expr 10 + 20)` |
| `PATH=/temp` 이후 모든 명령 실행 불가 | PATH 전체 덮어쓰기 | `export PATH=<원래 절대경로들>` 로 복구 |
| `${var}file` vs `$varfile` 결과 다름 | 변수명과 뒤 문자 구분 안 됨 | `${변수}` 형태로 명확히 구분 |

### 2-2. 메타문자 · 패턴

| 증상 | 원인 | 조치 |
| --- | --- | --- |
| 중괄호 확장이 문자 그대로 출력됨 | 콤마 뒤 공백 또는 전체를 따옴표로 감쌈 | 공백 제거, 중괄호 부분만 따옴표 밖에 |
| `rm -rf 패턴*` 로 의도보다 많이 삭제됨 | 패턴이 예상보다 넓게 매치 | 실행 전 `printf '%s\n' 패턴` 으로 대상 확인 |
| 작은따옴표 안에서 변수가 확장 안 됨 | 작은따옴표는 모든 메타문자 무력화 | 변수 확장이 필요하면 큰따옴표 사용 |
| `2>` 반복 실행 시 로그가 계속 덮어써짐 | `>` 계열은 매번 덮어쓰기 | 누적 기록은 `2>>` (append) 사용 |
| `PATH2="my value"` 참조 시 단어가 쪼개짐 | 따옴표 없이 `$변수` 참조 (word splitting) | 항상 `"$변수"` 로 참조 |

### 2-3. exit · test 조건

| 증상 | 원인 | 조치 |
| --- | --- | --- |
| `[$x -gt $y]` 문법 오류 | 대괄호 양쪽 공백 누락 | `[ $x -gt $y ]` |
| 문자열인데 `-eq` 등 숫자 연산자 사용 | 숫자/문자열 비교 연산자 혼동 | 문자열은 `=`/`!=`/`-z`/`-n` 사용 |
| 변수가 비어 있을 때 조건문 문법 오류 | 따옴표 없이 참조해 토큰이 사라짐 | `[ "$x" = "$y" ]` |
| `test` 결과가 화면에 안 보임 | test는 종료 코드만 반환, 자동 출력 없음 | `$?`, `&&`/`||`, `if` 와 함께 사용 |
| exit code 원인 파악이 안 됨 | 코드별 의미를 모름 | 127=명령없음, 126=권한문제, 128+N=신호종료 |
| `systemctl status` 결과를 `$?` 로 판정했더니 실패 처리됨 | 정지 상태면 종료 코드 `3` 반환 | 활성 여부는 `systemctl is-active` 로 확인 |

### 2-4. 조건문(if/case)

| 증상 | 원인 | 조치 |
| --- | --- | --- |
| 스크립트 실행 시 `Permission denied` | 실행 권한(x) 없음 | `chmod +x <스크립트>` |
| `if [ $x -gt 0 ]` 예상과 다른 분기 | 변수 비어있음/따옴표 누락 | `if [ "$x" -gt 0 ]` |
| `case` 에서 `*)` 분기만 계속 실행됨 | 대소문자 불일치/따옴표 누락 | `case "$변수" in`, 필요 시 `shopt -s nocasematch` |
| `read -s` 후 다음 출력이 같은 줄에 붙음 | `-s` 는 줄바꿈 자동 처리 안 함 | `read -s ...` 직후 `echo` 추가 |
| `read -t` 시간 초과 후 로직이 비정상 진행 | 실패 여부를 확인하지 않음 | `if ! read -t N ...; then exit 1; fi` |

### 2-5. 반복문(for/while/until)

| 증상 | 원인 | 조치 |
| --- | --- | --- |
| `for i in {1..$max}` 확장 안 됨 | 중괄호 확장은 변수 인식 불가 | `for (( i=1;i<=max;i++ ))` 또는 `for i in $(seq 1 "$max")` |
| `break` 가 바깥 루프까지 종료 안 시킴 | `break` 는 가장 안쪽 루프만 종료 | `break 2` 로 레벨 지정 또는 플래그 변수 사용 |
| `while` 무한 루프 | 카운터 증가/조건 변경 로직 누락 | 루프 본문 끝에 `((count++))` 등 반드시 포함 |
| `until` 폴링이 CPU를 과점유 | `sleep` 없이 조건만 반복 확인 | 루프 안에 `sleep N` 포함 |
| 대량 작업 중 `chown`/`chmod` 실패가 무시됨 | 단계별 `$?` 확인 없이 진행 | 각 단계 후 `$?` 확인 + 실패 시 `continue` |

### 2-6. 배열(Array) · RANDOM

| 증상 | 원인 | 조치 |
| --- | --- | --- |
| `for item in "${arr[*]}"` 가 1회만 실행됨 | `[*]` 는 배열을 하나의 문자열로 결합 | 개별 순회는 `"${arr[@]}"` 사용 |
| `${#arr}` 결과가 요소 개수와 다름 | `${#arr}` = `${#arr[0]}` = 0번 요소 문자 길이 | 요소 개수는 `${#arr[@]}` |
| `unset 'arr[2]'` 후 반복에서 빈 값·누락 발생 | `unset` 은 인덱스를 재정렬하지 않음(희소 배열) | `for i in "${!arr[@]}"` 또는 `arr=("${arr[@]}")` |
| 공백 포함 값이 여러 요소로 쪼개짐 | 선언/참조 시 따옴표 누락 | `arr=("kim lee" "park")`, `"${arr[@]}"` |
| 연관 배열에서 값이 서로 덮어써짐 | `declare -A` 선언 누락 → 첨자가 산술 평가(0) | `declare -A map` 먼저 선언 |
| `${arr[-1]}` 문법 오류 | 음수 인덱스는 Bash 4.3+ | `echo $BASH_VERSION` 확인 후 `${arr[${#arr[@]}-1]}` 사용 |
| `RANDOM % 101` 분포가 균일하지 않음 | 32768이 101의 배수가 아님(모듈로 편향) | 균일성 필요 시 `shuf -i 0-100 -n 1` |
| `RANDOM` 으로 임시 비밀번호 생성 | 예측 가능(보안 용도 부적합) | `openssl rand -base64 12` 또는 `/dev/urandom` |

### 2-7. 위치 매개변수(Positional Parameters)

| 증상 | 원인 | 조치 |
| --- | --- | --- |
| `$10` 이 10번째 인자가 아님 | `$1` + 문자 `0` 으로 해석 | `${10}` 중괄호 필수 |
| 공백 포함 파일명 인자가 두 개로 쪼개짐 | `"$1"`/`"$@"` 따옴표 누락 | 항상 `"$1"`, 전체 전달은 `"$@"` |
| `"$@"` 대신 `"$*"` 를 넘겨 명령이 실패 | 전체가 하나의 인자로 합쳐짐 | 다른 명령에 넘길 때는 `"$@"` |
| `[[ "$1" =~ ^[0-9]+$ ]]` 문법 오류 | `sh script.sh` 실행(Bash 확장 미지원) | `#!/bin/bash` + `./script.sh` 실행 |
| 정수 검증이 음수를 거부함 | `^[0-9]+$` 는 부호 불허 | 음수 허용은 `^-?[0-9]+$` |
| 인자 일부만 검증해 잘못된 값이 통과 | `$1`,`$2` 만 확인하고 가변 인자 미검증 | `for arg in "$@"` 로 전체 순회 검증 |
| 빈 값으로 파괴적 명령이 실행됨 | 개수·존재 검증 누락 | `[ $# -eq 1 ] && [ -d "$1" ] || exit 1` |
| 함수 안에서 `$1` 이 스크립트 인자가 아님 | 함수 내 `$1` 은 함수 인자 | 전역 변수에 저장 후 명시적으로 전달 |
| `shift` 후 원본 인자 목록이 사라짐 | `shift` 는 위치 매개변수를 파괴적으로 변경 | 필요하면 `targets=("$@")` 로 먼저 백업 |

### 2-8. cron · anacron

| 증상 | 원인 | 조치 |
| --- | --- | --- |
| 수동 실행은 되는데 cron에서 실행 안 됨 | cron 환경의 PATH 제한 (`/sbin:/bin:/usr/sbin:/usr/bin`) | 스크립트 내 명령어 절대 경로 사용 또는 crontab 상단에 `PATH=` 선언 |
| cron 작업 결과를 확인할 수 없음 | cron은 화면 출력이 없어 결과가 사라짐 | `>> /var/log/script.log 2>&1` 로 리다이렉션 후 `tail -f` |
| `run-parts`가 스크립트를 실행하지 않음 | 파일명에 `.sh` 확장자 있거나 실행 권한 없음 | 확장자 제거 + `chmod +x`, `run-parts --test` 로 사전 확인 |
| 등록한 cron 작업이 전혀 실행되지 않음 | crond 중지 / 등록 누락 / 권한 없음 | `systemctl status crond` → `crontab -l` → `chmod +x` → 절대 경로 순으로 진단 |
| anacron 작업이 같은 날 재실행 안 됨 | `/var/spool/anacron/`에 실행 날짜 기록, 당일 중복 실행 방지 | `anacron -n -f` (지연 생략 + 날짜 무관 강제 실행) |
| 스크립트 내 환경 변수가 cron에서 인식 안 됨 | cron은 최소한의 환경 변수만 제공 | 스크립트 내에서 직접 `export VAR=값` 선언 또는 절대 경로 사용 |
| 로그에 날짜 대신 `%f` 또는 마이크로초 출력 | `date +%f`(소문자) 사용 → YYYY-MM-DD 아님 | `date +%F`(대문자 F) 사용, 날짜+시간은 `date '+%F %T'` |
| anacron 작업 당일 재실행 안 됨 | `/var/spool/anacron/`에 실행 날짜 기록, 중복 방지 | `anacron -n -f`(지연 생략 + 날짜 무관 강제 실행) |
| `run-parts`가 daily_test.sh를 실행하지 않음 | 파일명에 `.sh` 확장자 있으면 제외 대상 | 파일명에서 확장자 제거, `run-parts --test` 로 사전 확인 |
| cron 종료 코드가 0인데 작업이 실패한 것처럼 보임 | cron 자체 종료와 스크립트 내부 exit 코드 혼동 | `tail /var/log/cron` + 스크립트 로그 파일 동시 확인 |

## 핵심 진단 명령어 모음 (Verification)

```bash
bash -n <스크립트>              # 문법만 사전 검사 (실행 안 함)
bash -x <스크립트> arg1 arg2     # 인자·배열 전개 과정 추적 (가장 강력)
echo $?                        # 직전 명령/스크립트 종료 코드
echo "$변수"                    # 변수 실제 값 확인 (따옴표로 감싸서)
declare -p <배열명>              # 배열 인덱스+값 구조 전체 확인
echo "${!arr[@]}"               # 인덱스 연속성 확인 (희소 배열 진단)
printf '[%s]\n' "${arr[@]}"     # 요소 경계 확인 (공백 포함 값 진단)
printf '[%s]\n' "$@"            # 인자 경계 확인
echo "$#"                       # 전달된 인자 개수 확인
printf '%s\n' <패턴>             # 글롭/중괄호 확장 결과 실행 전 미리보기
type <명령어>                    # 외부 명령/내장 명령/별칭 구분
env | grep <변수명>              # 환경 변수 등록 여부 확인
ls -l <스크립트>                 # 실행 권한(x) 여부 확인
stat -c "%U %G %a %n" <경로>     # 소유자/그룹/권한/경로 한 번에 확인
echo $BASH_VERSION              # 연관 배열(4.0+)·음수 인덱스(4.3+) 지원 확인
```

## 트러블슈팅 시나리오 상세

### 🚨 시나리오 1. 변수 계산 결과가 이어붙은 문자열로 출력

```bash
$ num1=10; num2=20
$ echo $num1+$num2
10+20                    # 30이 아님
```

**해결**: `echo $(( num1 + num2 ))`

### 🚨 시나리오 2. 중괄호 확장에 변수를 사용해 반복문이 동작하지 않음

```bash
$ max=5
$ for i in {1..$max}; do echo $i; done
{1..5}                    # 문자 그대로 출력, 반복 안 됨
```

**해결**:

```bash
for (( i=1; i<=max; i++ )); do echo "$i"; done
```

### 🚨 시나리오 3. case 문에서 기본 분기(`*`)만 계속 실행

```bash
$ read -p "y/n : " answer
$ case $answer in           # 따옴표 없이 사용
      y) echo "YES";;
      *) echo "잘못된 입력";;
  esac
```

**해결**:

```bash
case "$answer" in
    y|Y) echo "YES";;
    n|N) echo "NO";;
    *) echo "잘못된 입력";;
esac
```

### 🚨 시나리오 4. while 카운터 누락으로 무한 루프

```bash
count=1
while [ "$count" -le 3 ]
do
    echo "시도 $count"
    # count 증가 로직 누락 -> 무한 반복
done
```

**해결**:

```bash
count=$((count + 1))    # 루프 본문 마지막에 반드시 포함
```

### 🚨 시나리오 5. unset 후 인덱스가 어긋나 배열 반복이 깨짐

```bash
$ name=("kim" "lee" "park" "ryu")
$ unset 'name[2]'
$ echo "${#name[@]}" ; echo "${!name[@]}"
3
0 1 3                                   # 인덱스 2가 비어 있음

$ for ((i=0;i<${#name[@]};i++)); do echo "$i : ${name[i]}"; done
0 : kim
1 : lee
2 :                                      # 빈 값, ryu 누락
```

**해결**:

```bash
for i in "${!name[@]}"; do echo "${name[i]}"; done   # 인덱스 목록 기준
name=("${name[@]}")                                   # 또는 인덱스 재정렬
```

### 🚨 시나리오 6. 공백 포함 인자가 두 개로 쪼개져 처리됨

```bash
$ ./bak.sh "my file.txt" /backup
# 스크립트 내부에서 cp $1 $2 로 작성한 경우
cp: 'my' 파일이나 디렉터리가 없습니다
```

**원인**: 인자 참조 시 따옴표를 생략해 단어 분리(word splitting) 발생.
**해결**:

```bash
cp -- "$1" "$2"
```

### 🚨 시나리오 7. 가변 인자 검증을 앞 두 개만 해서 잘못된 값이 통과

```bash
# $1, $2 만 정수 검증한 스크립트
$ ./sum.sh 10 20 A
인자 개수 : 3
인자 총합 : 30            # A가 검증을 통과해 결과가 잘못됨
```

**해결**:

```bash
for num in "$@"
do
    [[ "$num" =~ ^-?[0-9]+$ ]] || { echo "정수가 아닌 값 : $num"; exit 1; }
done
```

### 🚨 시나리오 8. 백업 파일명에 콜론이 들어가 전송·복원에서 실패

```bash
$ ls /backup/
sqlDB_2026-07-29_17:13:39.tar.gz         # date +%T 사용 결과
```

**원인**: 콜론은 `scp host:path` 문법과 충돌하고 일부 파일시스템에서 사용할 수 없다.
**해결**: `date +%F_%H%M%S` 형식으로 변경한다.

### 🚨 시나리오 9. 파괴적 명령에 글롭 패턴을 확인 없이 바로 실행

```bash
rm -rf /backup/a*      # 예상보다 많은 파일이 삭제될 위험
rm -rf "$1"/*          # $1 이 비어 있으면 / 하위가 대상
```

**해결**:

```bash
[ -n "$1" ] && [ -d "$1" ] || { echo "Usage : $0 <dir>"; exit 1; }
printf '%s\n' "$1"/*          # 삭제 전 대상 목록 확인
rm -rf "$1"/*                 # 확인 후 실행
```
