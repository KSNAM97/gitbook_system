# Shell Script - 통합 정리 (변수부터 cron · anacron까지 한눈에)

쉘 스크립트는 **변수(문자열 저장) → 메타문자(패턴·치환·연결) → 산술 도구(expr/let/`$(( ))`) → 종료 코드·test(조건 판단의 단위) → 조건문(if/case) → 반복문(for/while/until) → 배열(다수 값 관리) → 위치 매개변수(외부 값 주입) → cron·anacron(시간 기반 자동화)** 순서로 계층을 쌓아 올라가는 구조다. 이 문서는 1~9번 문서를 한 장으로 닫는 색인이다.

## 개요 (Overview)

쉘 스크립트 전체를 관통하는 단 하나의 원리는, 모든 것이 **문자열**과 **종료 코드(exit status)** 두 가지로 판정된다는 것이다. 변수·배열 요소·위치 매개변수는 예외 없이 문자열로 저장되고, 조건문·반복문의 참/거짓 판단은 명령의 종료 코드(0=참, 0 이외=거짓)를 기준으로 한다. 산술 연산이 필요하면 반드시 `$(( ))`, `expr`, `let` 같은 별도 구문을 거쳐야 하며, 배열 요소(`${arr[0]}`)도, 위치 매개변수(`$1`)도 그대로는 계산되지 않는다. 조건 판단은 `test`(`[ ]`)가 반환하는 종료 코드가 `if`/`while`/`until`/`&&`/`||` 전체의 공통 기반이며, 스크립트 자신도 `exit N` 으로 종료 코드를 남겨 호출한 쪽(cron·상위 스크립트)에 성공/실패를 알린다.

8개 계층은 서로 연결되어 있다. 위치 매개변수가 외부에서 값을 받아오는 **입구**, 배열이 그 값들을 담아 두는 **그릇**, 메타문자가 값을 가공하는 **문법**, 산술 도구가 **수치 계산**, test가 **판정 단위**, 조건문·반복문이 **흐름 제어**를 담당한다. 즉 위치 매개변수 → 배열 → 반복문 → 조건문으로 데이터가 흐르고, 그 사이를 메타문자와 산술 구문이 잇는다. 예를 들어 `./bak.sh /var/log /backup` 을 실행하면 `src="$1"` (위치 매개변수) → `files=("$src"/*.log)` (글롭 + 배열) → `for f in "${files[@]}"` (반복문) → `if [ -s "$f" ]` (조건) → `size=$(( bytes / 1024 ))` (산술) → `exit 0` 순으로 흐른다. `"$@"` 와 `"${arr[@]}"` 는 문법 구조가 동일하며(개별 전개), `"$*"` 와 `"${arr[*]}"` 도 동일하게 하나의 문자열로 결합된다. 한 번 이해하면 두 곳에 그대로 적용된다. `$#`(인자 개수)과 `${#arr[@]}`(요소 개수)는 이름이 비슷하지만 대상이 다르므로 혼동에 주의한다.

값이 하나인가 여러 개인가, 내부 고정인가 외부 주입인가로 어떤 문법을 쓸지가 결정된다. 데이터의 성격을 **개수(1개/N개)** 와 **출처(내부 고정/외부 주입)** 두 축으로 나누면 어떤 문법을 쓸지 자동으로 정해진다.

| | 값 1개 | 값 여러 개 |
| --- | --- | --- |
| **스크립트 내부 고정** | 일반 변수 (`name="kim"`) | 배열 (`arr=("a" "b")`) |
| **외부에서 주입** | 위치 매개변수 (`$1`) / `read` | `"$@"` 전체 순회 / `arr=("$@")` |

대화형 실행이 전제되면 `read`, 자동화(cron·타이머·상위 스크립트 호출)가 전제되면 위치 매개변수를 쓴다. 둘을 섞을 때는 `[ -z "$1" ] && read -p "경로 : " src` 패턴을 사용한다. 외부 인자를 배열로 옮겨 담으면(`targets=("$@")`) 이후 `shift` 로 원본이 훼손되어도 목록이 보존된다.

실무 스크립트를 작성할 때는 ① 입력 계층 결정(인자/`read`) → ② 인자 검증(개수·형식·존재) 후 실패 시 즉시 `exit 1` → ③ 필요한 값을 변수/배열로 확보 → ④ 파일·경로 패턴은 메타문자(글롭·중괄호)로 정리 → ⑤ 수치가 필요하면 `$(( ))` 로 계산 → ⑥ `test`/`[ ]` 로 조건 검증 → ⑦ `if`/`case` 로 분기 → ⑧ 반복이 필요하면 `for`/`while`/`until` 로 감싸고 → ⑨ 마지막에 `exit` 코드로 결과를 명확히 반환하는 순서가 표준이다. 검증(②)을 본 로직보다 앞에 두는 것이 안전 설계의 핵심으로, 빈 값으로 `rm -rf "$1"/*` 이 실행되는 사고는 전부 이 단계를 건너뛴 결과다. 반복 안에서는 각 단계 `$?` 를 확인하고 실패 시 `continue` 로 다음 대상으로 넘기는 방어 패턴을 표준으로 삼는다.

cron은 스크립트를 자동 호출하는 **외부 진입점**이다. cron이 실행하는 스크립트 내부는 1~8번 모든 기법을 그대로 활용하며, 결과는 **종료 코드(exit status)**로 cron에게 반환된다. **위치 매개변수(8번)** 는 동일 스크립트에 여러 경로를 인자로 전달할 수 있게 해주는데, 단 cron은 대화형이 아니므로 인자를 `/etc/crontab`에 직접 적는다.

```bash
30 23 * * * root /script/logcheck.sh 50 /var/log/messages >> /var/log/check.log 2>&1
```

**조건문·반복문·배열(5~7번)** 은 스크립트 내부 로직을 그대로 사용한다. cron 실행 환경의 차이는 PATH 제한뿐이므로 명령 경로만 절대 경로로 바꾸면 된다. **종료 코드(4번)** 는 스크립트 마지막의 `exit 0`/`exit 1` 이 cron·상위 스크립트에게 성공/실패를 알리며, anacron 연동 패턴의 `test -x /usr/sbin/anacron || ...`도 종료 코드 기반 판정이다. **메타문자(2번)** 로는 `>> log 2>&1` (리다이렉션), `find -print -delete` (파이프 없이 -delete로 직결), `tar czf` (압축) 모두 cron 스크립트에서 핵심적으로 사용된다. **cron 핵심 3원칙**은 **절대 경로** · **실행 권한(`chmod +x`)** · **출력 리다이렉션(`>> log 2>&1`)** 이며, 이 세 가지를 지키지 않으면 터미널에서는 되는데 cron에서는 안 되는 현상이 발생한다.

## 표준 개념 정리 (Configuration)

> **적용 환경:** Bash 기반 Linux 셸 환경 (RHEL 계열 기본 `/bin/bash`).

### Step 1. 9대 문서 요약 흐름도

```text
[1] 변수·환경변수        → 값을 저장/전달 (문자열 기본, export로 자식 프로세스 전달)
[2] Metacharacters      → 패턴 매칭·치환·리다이렉션·명령 연결의 공통 문법
[3] expr·let            → 정수 산술 계산 (외부 명령 expr / 내장 명령 let)
[4] exit·test           → 종료 코드 판정 + 파일/문자열/숫자 조건 검사
[5] 조건문(if/case)      → 종료 코드를 기준으로 분기 실행
[6] 반복문(for/while/until) → 정해진 목록/조건 기반 반복 실행
[7] 배열(Array)          → 여러 값을 인덱스로 묶어 관리 (반복문의 순회 대상)
[8] 위치 매개변수        → 실행 시점에 외부 값을 주입 (자동화 스크립트의 진입점)
[9] cron·anacron        → 시간 기반 자동 실행 (crond·crontab·anacron 연동)
```

### Step 2. 값 참조 · 산술 · 조건 문법 비교표

| 구분 | 문법 | 반환 방식 |
| --- | --- | --- |
| 변수 참조 | `$변수`, `"$변수"` | 문자열 값 |
| 배열 요소 참조 | `"${arr[0]}"` | 문자열 값 |
| 배열 전체 참조 | `"${arr[@]}"` / `"${arr[*]}"` | 개별 전개 / 문자열 결합 |
| 배열 개수·인덱스 | `${#arr[@]}` / `${!arr[@]}` | 요소 개수 / 인덱스 목록 |
| 인자 참조 | `"$1"`, `"$@"`, `"$*"` | 문자열 값 / 개별 전개 / 결합 |
| 인자 개수 | `$#` | 정수(문자열) |
| 명령 치환 | `$(명령)` | 명령의 표준출력 |
| 산술 확장 | `$(( 산술식 ))` | 계산 결과값 |
| 산술 평가 | `(( 산술식 ))` | 종료 코드(0=참/1=거짓) |
| 조건 검사 | `test`, `[ 조건 ]` | 종료 코드(0=참/1=거짓) |
| 정규식 검사 | `[[ "$1" =~ ^[0-9]+$ ]]` | 종료 코드(Bash 전용) |

### Step 3. 조건문 · 반복문 · 배열 · 인자 골격 한 장 요약

```bash
# if 3형식
if [ 조건 ]; then 명령; fi
if [ 조건 ]; then 명령1; else 명령2; fi
if [ 조건1 ]; then 명령1; elif [ 조건2 ]; then 명령2; else 명령3; fi

# case (여러 패턴 비교 시 if-elif보다 간결)
case "$변수" in
    패턴1) 명령1 ;;
    패턴2|패턴3) 명령2 ;;
    *) 기본실행문 ;;
esac

# for : 정해진 목록 순회
for 변수 in 값1 값2 값3; do 명령; done
for (( i=1; i<=N; i++ )); do 명령; done       # 변수 범위가 필요할 때 표준

# while / until
while [ 조건 ]; do 명령; done                  # 참인 동안
until [ 조건 ]; do 명령; done                  # 거짓인 동안

# 배열 순회
for item in "${arr[@]}"; do 명령; done         # 값 기준
for i in "${!arr[@]}"; do 명령; done           # 인덱스 기준(희소 배열 안전)

# 위치 매개변수 순회
for arg in "$@"; do 명령; done
while [ $# -gt 0 ]; do 명령; shift; done       # shift 방식
```

### Step 4. 자동화 스크립트 표준 골격 (8계층 전체 조합)

```bash
#!/bin/bash
# 사용법 : ./logcheck.sh <임계값MB> <로그경로1> [로그경로2 ...]

# ① 입력 검증 (개수 → 형식) : 본 로직보다 항상 먼저
if [ $# -lt 2 ]
then
    echo "Usage : $0 <limit_MB> <logfile1> [logfile2 ...]"
    exit 1
fi

if ! [[ "$1" =~ ^[0-9]+$ ]]
then
    echo "임계값은 정수여야 한다 : $1"
    exit 1
fi

# ② 인자를 변수·배열로 확보 (shift로 첫 인자 소비 후 나머지를 목록으로)
limit="$1"; shift
targets=("$@")

warn=0
ok=0

echo "임계값 : ${limit}MB / 점검 대상 : ${#targets[@]}개"
echo "-----------------------------"

# ③ 배열 순회 + 조건 검증 + 산술 계산 (실패 시 continue 방어)
for file in "${targets[@]}"
do
    if [ ! -f "$file" ]
    then
        echo "$file : 파일 없음 (건너뜀)"
        continue
    fi

    size=$(du -m "$file" 2>/dev/null | awk '{print $1}')   # 명령 치환

    if (( size >= limit ))                                  # 산술 평가
    then
        echo "$file : 용량 초과 (${size}MB)"
        (( warn++ ))
    else
        echo "$file : 정상 (${size}MB)"
        (( ok++ ))
    fi
done

echo "-----------------------------"
echo "정상 ${ok}개 / 경고 ${warn}개"

# ④ 결과를 종료 코드로 반환 (호출한 쪽에서 판정 가능)
(( warn > 0 )) && exit 1
exit 0
```

```bash
chmod +x ./script/logcheck.sh
./script/logcheck.sh 50 /var/log/messages /var/log/secure /var/log/cron
echo $?                                  # 경고가 있으면 1, 모두 정상이면 0
```

### 3-2. 대표 함정 요약

| 함정 | 결과 | 정답 |
| --- | --- | --- |
| `echo $a+$b` | 문자열 그대로 이어붙음 | `echo $(( a + b ))` |
| 공백 있는 값을 따옴표 없이 대입 | 여러 명령/인자로 잘못 분리 | `변수="값 값"` 로 겹따옴표 사용 |
| `[$x -gt $y]` | 문법 오류 | 대괄호 양쪽 공백 필수 `[ $x -gt $y ]` |
| `{1..$max}` | 확장 안 됨(리터럴 그대로) | `for (( i=1;i<=max;i++ ))` 또는 `seq` |
| `case` 변수 따옴표 누락 | 공백값에서 패턴 불일치 | `case "$변수" in` |
| `while` 카운터 증가 누락 | 무한 루프 | 루프 본문 끝에 카운터 증가 로직 필수 |
| `${#arr}` 로 개수 확인 | 0번 요소의 문자 길이 반환 | 개수는 `${#arr[@]}` |
| `"${arr[*]}"` 로 순회 | 반복이 1회만 실행 | 순회는 `"${arr[@]}"` |
| `unset 'arr[2]'` 후 인덱스 가정 | 인덱스 불연속(희소 배열) | `for i in "${!arr[@]}"` 또는 `arr=("${arr[@]}")` |
| `$10` 으로 10번째 인자 참조 | `$1` + 문자 `0` 으로 해석 | `${10}` 중괄호 필수 |
| 인자 검증 없이 본 로직 실행 | 빈 값으로 파괴적 명령 수행 | 개수·형식·존재 3단 검증 후 `exit 1` |
| `sh script.sh` 로 `**=~**` 사용 | 문법 오류 | `#!/bin/bash` + `./script.sh` 실행 |

## 요약
-  **핵심 요약**
- 모든 판정은 **문자열(값) + 종료 코드(조건)** 두 축으로 귀결
- 계산은 항상 별도 구문(`$(( ))`/`expr`/`let`) 경유
- `"$@"` 와 `"${arr[@]}"` 는 동일 구조(개별 전개), `"$*"`/`"${arr[*]}"` 는 문자열 결합
- 실무 설계 순서 : 입력 → 검증 → `exit 1` → 값 확보 → 계산 → 조건 → 분기 → 반복 → exit 코드
