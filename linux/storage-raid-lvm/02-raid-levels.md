# 📊 RAID 레벨별 특징 (Linear·0·1·5·6)

> **Tag:** #Linux #RAID #RAID0 #RAID1 #RAID5 #RAID6 #Parity #FaultTolerance
> **핵심 요약:** Software RAID의 대표 레벨은 Linear, RAID 0, RAID 1, RAID 5, RAID 6이며 성능(Performance)·안정성(Reliability)·공간 효율성(Storage Efficiency)에서 차이가 있다. Linear·RAID 0은 결함 허용이 없고, RAID 1은 미러링으로 안정성이 높으며, RAID 5는 패리티 1개로 디스크 1개, RAID 6은 패리티 2개로 디스크 2개 장애까지 복구할 수 있다.

---

## 1. 📖 개요 (Overview)

Linear RAID는 최소 2개 이상의 디스크를 하나의 논리 디스크로 묶되, 데이터를 **첫 번째 디스크부터 순차적으로 채워 나가는** 방식입니다. 결함 허용(Fault-tolerance)을 제공하지 않으며 읽기·쓰기 처리 능력도 낮은 편이지만, 디스크 용량을 **손실 없이 100% 합산**해서 사용할 수 있다는 것이 장점입니다.

```text
HDD1(1T) + HDD2(1T) + HDD3(1T) + HDD4(1T)   = 4T 사용
HDD1(10T) + HDD2(10T) + HDD3(10T) + HDD4(10T) = 40T 사용
HDD1(10T) + HDD2(1T) + HDD3(1T) + HDD4(1T)   = 13T 사용 (용량이 달라도 전량 합산)
```

디스크 하나가 고장 나면 그 디스크에 저장된 데이터만이 아니라, 순차 저장 구조 특성상 **전체 파일시스템이 깨질 위험**이 큽니다.

RAID 0(Striping)은 최소 2개 이상의 디스크에 데이터를 **분할(스트라이핑)해서 동시에** 저장합니다. Linear보다 읽기·쓰기 처리 능력이 빠르지만, 디스크 중 하나라도 고장 나면 **전체 데이터가 손상**되며 결함 허용을 제공하지 않습니다.

```text
모든 HDD 크기가 동일 → 100% 활용
크기가 다르면 → 가장 작은 HDD 용량 기준으로 각 디스크가 동일하게 사용

HDD1(10T) + HDD2(1T) + HDD3(1T) + HDD4(1T) = 4T 사용 (1T 기준 × 4)
```

성능이 최우선이고 **잃어도 문제 없는 데이터**(캐시, 임시 스크래치 공간 등)에만 사용을 권장합니다.

RAID 1(Mirroring)은 최소 2개 이상의 디스크에 **같은 데이터를 복제 저장**합니다. 필요한 용량의 2배 이상을 구성해야 하므로 공간 효율은 낮지만(약 50%), 결함 허용을 제공해 신뢰성이 높고 저장 속도도 기존과 비슷합니다. 중요한 데이터를 저장하기에 적합합니다. 디스크 1개가 고장 나도 나머지 미러 디스크로 즉시 서비스를 유지할 수 있습니다.

RAID 5는 **RAID 0의 공간 효율성·읽기 성능**과 **RAID 1 수준의 결함 허용**을 절충한, 가장 대중적인 RAID 레벨입니다. 최소 3개 이상의 디스크가 필요하며, 데이터를 블록 단위로 분산 저장하면서 **패리티(Parity) 비트를 함께 분산 저장**합니다. 디스크 1개 장애 시 남은 데이터 블록과 패리티로 복구할 수 있습니다.

공간 효율성은 **"디스크 개수 − 1"** 로 계산합니다.

| 구성 | 공간 효율성 |
|---|---|
| 1T × 3개 | 약 66% |
| 1T × 4개 | 75% |
| 1T × 5개 | 80% |
| 1T × 10개 | 90% |
| 1T × 100개 | 99% |

```text
Data = 000 001 010 011

HDD1   HDD2   HDD3   HDD4     복구 예(HDD2 장애 시)
  0      0      0     P0            0
  0      0      P1     1            0
  0      P2     1      0            1
  P3     0      1      1            0
```

**복구(rebuild)가 끝나기 전에 또는 동시에 디스크 2개가 고장 나면 데이터를 복구할 수 없습니다.** 패리티 계산·쓰기 부하 때문에 쓰기 성능(특히 랜덤 쓰기)은 RAID 0·10보다 느릴 수 있습니다. 일반적으로 디스크 10개 이하 구성에서 RAID 5를 많이 사용합니다.

RAID 6는 RAID 5의 개량형으로 최소 4개 이상의 디스크가 필요합니다. **패리티를 2개** 사용하기 때문에 RAID 5보다 공간 효율은 낮지만, **디스크 2개가 동시에 장애**가 발생해도 복구할 수 있어 안정성이 더 높습니다.

```text
RAID 5 공간 효율성 = HDD 개수 - 1  (패리티 1개)
RAID 6 공간 효율성 = HDD 개수 - 2  (패리티 2개)

1T × 4개 → 2T (50%)
1T × 5개 → 3T (60%)
1T × 6개 → 4T (66%)
```

쓰기 성능은 RAID 5보다 다소 떨어질 수 있습니다. 디스크 용량이 커질수록 복구 시간이 길어지므로, 대용량 디스크 환경에서는 RAID 6의 이중 패리티 안정성이 유리합니다. 대용량 파일 서버, DB 백업 서버, VM 클러스터 스토리지 등에서 RAID 6 또는 RAID 10이 표준처럼 사용됩니다.

RAID 레벨을 한눈에 비교하면 다음과 같습니다.

| 레벨 | 최소 디스크 | 결함 허용 | 공간 효율 | 특징 |
|---|---|---|---|---|
| Linear | 2 | 없음 | 매우 높음(합산) | 순차 저장, 성능 낮음 |
| RAID 0 | 2 | 없음 | 높음(최소 디스크 기준) | 스트라이핑, 빠름 |
| RAID 1 | 2 | 있음(1개) | 낮음(약 50%) | 미러링, 안정성 높음 |
| RAID 5 | 3 | 있음(1개) | 높음(N−1) | 패리티 1개, 대중적 |
| RAID 6 | 4 | 있음(2개) | 중간(N−2) | 패리티 2개, 안정성 높음 |

> 공간 효율과 결함 허용은 트레이드오프 관계입니다. 데이터 중요도가 낮고 성능이 중요하면 RAID 0, 중요도가 높으면 RAID 1·5·6을 검토합니다.

## 2. 🛠️ 표준 설정 참고 (Configuration)

### 2-1. RAID용 파티션 타입 지정

```bash
fdisk /dev/sdb
```

```text
n → p → 1 → Enter → Enter     # 파티션 생성
t → fd                        # 타입을 Linux raid autodetect(fd)로 변경
w                              # 저장
```

확인:

```bash
lsblk                          # 파티션 생성 확인
fdisk -l /dev/sdb | grep raid  # raid 타입 파티션 확인
```

> 파티션 타입 `fd`(Linux raid autodetect)는 관례적인 표식이며, `mdadm`은 파티션 타입과 무관하게 슈퍼블록으로 RAID를 인식할 수 있습니다. LVM용 파티션(`8e`)과 혼동하지 않도록 주의합니다.

### 2-2. 레벨별 생성 형식 요약

```bash
mdadm --create /dev/md0 --level=linear --raid-devices=2 /dev/sdb1 /dev/sdc1
mdadm --create /dev/md0 --level=0      --raid-devices=2 /dev/sdb1 /dev/sdc1
mdadm --create /dev/md0 --level=1      --raid-devices=2 /dev/sdb1 /dev/sdc1
mdadm --create /dev/md5 --level=5      --raid-devices=4 /dev/sdb1 /dev/sdc1 /dev/sdd1 /dev/sde1
mdadm --create /dev/md6 --level=6      --raid-devices=4 /dev/sdb1 /dev/sdc1 /dev/sdd1 /dev/sde1
```

## 3. 🔍 검증 및 트러블슈팅 (Verification & Troubleshooting)

### 3-1. 레벨과 상태 확인

```bash
mdadm --detail /dev/md5       # RAID 레벨·상태·구성원 확인
cat /proc/mdstat              # 동기화·복구 진행률 확인
```

`Raid Level` 항목에서 실제 구성된 레벨을, `State` 항목에서 `clean`(정상)·`degraded`(디스크 부족)·`recovering`(복구 중) 상태를 확인합니다.

### 3-2. 공간 효율 계산

```text
RAID 5 사용 가능 용량 ≈ (디스크 개수 - 1) × 최소 디스크 용량
RAID 6 사용 가능 용량 ≈ (디스크 개수 - 2) × 최소 디스크 용량
```

### 3-3. 레벨 선택 시 흔한 실수

| 실수 | 결과 | 정답 |
|---|---|---|
| 중요 데이터를 RAID 0에 저장 | 디스크 1개 고장으로 전체 손실 | RAID 1·5·6 사용 |
| RAID 5에서 디스크 2개 동시 장애 대비 안 함 | 복구 불가 | 중요도 높으면 RAID 6·10 검토 |
| RAID를 백업으로 오해 | 논리적 손상·삭제 대응 불가 | RAID + 별도 백업 병행 |

> 📌 **핵심 요약**
> - Linear·RAID 0은 결함 허용 없음
> - RAID 1은 미러링, 안정성 높고 효율 낮음
> - RAID 5는 패리티 1개로 디스크 1개 장애 복구(N−1)
> - RAID 6는 패리티 2개로 디스크 2개 장애 복구(N−2)
> - 공간 효율과 결함 허용은 트레이드오프
